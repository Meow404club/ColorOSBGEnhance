# 常见问题

## 首页显示“模块尚未生效”

请依次确认：

1. LSPosed 中已经启用本模块；
2. 作用域中已经勾选“系统框架”和“Athena”；
3. 安装、更新或修改作用域后已经重启手机；
4. 重启后没有再次关闭模块或作用域。

首页只接受本次开机的功能状态，旧记录不会被当成当前已生效。如果刚完成重启，可以稍候片刻后点击重新检测。

## 页面提示需要重启

模块代码运行在系统框架和 Athena 进程中。首次启用、修改作用域或更新 APK 后，旧进程仍可能运行旧代码，因此需要完整重启。

普通功能开关和应用驻留规则通常不需要重启。保存页面会在设置仍在同步时显示等待提示，不要把“正在同步”误认为必须重启。

## 设置同步异常

进入运行诊断，点击重新检测。如果仍然异常：

1. 确认 LSPosed 中模块和两个作用域仍然启用；
2. 确认模块应用没有被系统限制运行；
3. 稍候后重新打开页面；
4. 问题持续时重启手机。

设置暂时不可用时，模块会优先安全放行，不会继续执行无法确认的旧限制性策略。

## 部分功能显示不可用

这表示当前系统版本没有找到该功能需要的经过验证接口，或安装过程出现异常。对应功能会保持系统原行为，其他功能仍可继续工作。

请在“功能状态”页重新检测并导出诊断信息。不要通过打开更多高风险选项来尝试修复加载问题。

## 应用驻留规则没有效果

请确认：

- 主页“启用后台保护”总开关已经开启；
- 该应用规则处于启用状态，并且不是“系统管理”；
- 观察模式已经关闭；
- 保存页面没有显示设置仍在同步或部分功能不可用；
- 当前现象确实来自系统后台管理，而不是应用崩溃、自行退出、用户强行停止或极端内存回收。

“均衡”允许应用被系统冻结。冻结后应用暂时不运行，但进程仍可保留在内存中；这不表示驻留规则失效。

## 消息或定时任务出现延迟

“低功耗”模式会限制频繁的网络消息和定时任务唤醒；自定义模式也可能阻止必要唤醒或缩短再次冻结等待时间。

先改回“均衡”观察。如果应用依赖持续工作，可以谨慎使用“活跃”，但待机耗电和内存占用可能增加。

## 开启“保留网络连接”后仍然断网

此选项只控制已经验证的后台冻结网络限制路径。系统、网络环境、应用自身重连逻辑以及其他未覆盖的 socket 处理仍可能造成连接中断，因此它不等于完整的不断网保证。

## 运行记录全部为 0

零记录通常表示相应场景尚未发生，不代表功能一定异常。受管理应用和固定行为类别会在没有事件时仍显示为 0。

如果正常使用较长时间后，所有行为和所有功能命中仍然始终为 0，请进入“功能状态”确认系统框架、Athena 和各项功能均已加载。

## 为什么出现“安全放行”

当设置、应用身份、系统接口或内部状态无法可靠确认时，模块会执行系统原行为，避免造成系统服务异常。安全放行是保护性设计；持续大量出现时应导出诊断信息排查。

## 清除记录后功能状态为什么还在

清除操作会删除用户活动和统计，但会保留本次开机的功能加载状态，方便继续判断模块是否正常工作。清除记录不会改变保护设置或应用规则。

## 如何反馈问题

先进入运行诊断并点击重新检测。默认“复制诊断信息”会生成脱敏内容，适合一般排查。

只有确实需要应用和系统细节时才使用完整文件导出。应用会先确认运行记录已经完整读取，再让你选择保存位置；分享前请检查内容，并只发送给可信的排查人员。

如果页面提示运行记录尚未完整读取，请稍后重新检测再保存。如果提示所选位置不支持安全写入，请选择其他位置。保存失败后若仍看到带有 `.partial` 标记的文件，可以直接删除；它不会被当作已完成报告。
