# ColorOS 后台增强

ColorOS 后台增强是一款 LSPosed 模块，用于减少 ColorOS/OPlus 系统过早结束后台应用，并让用户按应用选择冻结、唤醒和后台资源策略。

模块的目标是让后台应用尽量保留在内存中，而不是让所有应用始终运行。允许系统适时冻结应用，通常可以在恢复速度和待机耗电之间取得更好的平衡。

## 主要功能

- 后台清理保护：减少功耗管理、定期清理、相机、录像、游戏、AI、低内存和分组清理等场景主动结束应用；
- 应用驻留：为主应用和应用分身分别选择后台保护、冻结、唤醒、资源保留和再次冻结方式；
- 五种驻留模式：系统管理、均衡、低功耗、活跃和自定义；
- 安全恢复：关闭总开关后尽量恢复由系统接管；停用或删除单独规则后，应用仍遵循主页的全局保护模式；
- 运行诊断：按应用、后台行为和功能状态查看检测、阻止与异常放行记录；
- 旧策略导入：读取受支持的旧版冻结策略文件，预览差异后再选择性导入。

## 安装和启用

1. 安装模块 APK；
2. 在 LSPosed 中启用本模块；
3. 勾选“系统框架”和“系统后台管理服务（Athena）”作用域；
4. 重启手机；
5. 打开模块，确认首页不再显示“模块尚未生效”，并在“运行诊断”的“功能状态”中确认所需功能可用。

首次启用、修改 LSPosed 作用域或更新模块 APK 后需要重启。普通设置在同步正常时会自动应用，页面会在确实需要重启时给出提示。

使用同一发布签名的更新可以直接覆盖安装并保留应用设置。如果系统提示签名不一致、安装包冲突或无法覆盖，说明设备上的现有安装来自不同签名来源。卸载会清除模块应用内的设置和驻留规则，请先用截图或文字记录重要配置，再卸载旧安装、安装当前 APK、重新确认 LSPosed 启用状态和两个作用域，并按记录恢复设置后重启。不要通过关闭系统签名校验来强行覆盖。

## 全局保护模式

主页的保护模式控制通用后台清理行为，并适用于没有单独规则的普通应用：

- **均衡**：减少常见后台清理，兼顾系统稳定性；
- **增强**：开启更多保护，可能增加内存占用和待机耗电；
- **自定义**：逐项调整相机、游戏、低内存、分组清理和冻结相关功能。

只有选择“自定义”后，主页才会显示需要逐项调整的高级策略。

## 应用驻留

在主页进入“应用驻留”，可以在全局保护基础上为特定应用增加单独策略：

- **系统管理**：不增加单独保护，仍遵循主页的全局保护模式；
- **均衡**：尽量避免应用被主动结束，同时允许冻结和唤醒跟随系统；
- **低功耗**：保留应用进程，更积极地冻结并限制频繁唤醒；
- **活跃**：尽量避免冻结，适合确实需要持续工作的应用，耗电可能明显增加；
- **自定义**：分别设置后台保护、冻结来源、唤醒来源、后台资源和再次冻结时间。

对大多数希望“保留在内存、使用时快速恢复”的应用，建议先使用“均衡”。即时通信、闹钟、音乐和导航类应用不应随意阻止必要唤醒；修改前请阅读页面风险提示。

主应用和应用分身按包名与 Android 用户分别管理，可以独立添加、修改、停用和删除策略。未添加单独规则的实例遵循主页的全局保护模式。升级时，已有规则保留给主用户（用户 0）；旧冻结策略文件也导入到主用户。运行诊断按用户实例区分记录。

## 观察模式

观察模式只记录模块检测到的后台行为，不进行阻止。首次使用新策略时，可以先开启观察模式，确认运行记录符合预期后再正式启用保护。

## 运行诊断与导出

首页“运行记录”显示近期检测、阻止和异常放行汇总。进入运行诊断后，可以按应用、行为和功能状态查看详情；功能状态只表示本次开机。

默认复制的诊断信息会移除应用包名、UID、进程标识、开机标识和自由文本。复制内容会进入 Android 系统剪贴板，分享后建议及时清除。包含完整细节的文件只有在用户明确确认并选择保存位置后才会生成；分享前仍应检查文件内容。

如果运行记录尚未完整读取，应用会拒绝保存完整报告并提示稍后重试。保存失败时不会留下看起来已经完成的报告；如果页面提示所选位置仍有未完成文件，请删除带有 `.partial` 标记的文件。

## 能力边界

- 模块不会禁用系统的全局低内存兜底，极端内存压力下应用仍可能被系统低内存清理机制（LMKD）或内核回收；
- 用户主动强行停止、应用崩溃、应用自行退出和手机重启不属于后台保护范围；
- 不同系统版本的内部实现可能不同。找不到经过验证的系统接口时，对应功能会显示不可用并执行系统原行为；
- 后台资源选项只覆盖当前系统中已经验证的后台冻结处理路径；即使选择“尽量维持网络连接”，也不承诺连接始终不断开；
- 冻结或限制唤醒可能造成消息、定时任务和后台工作的延迟；完全避免冻结则可能明显增加耗电。

详细说明见 [使用说明](docs/user-guide.md) 和 [常见问题](docs/troubleshooting.md)。

## 隐私

模块不依赖云端服务。为了列出可选择的应用，并把运行记录中的系统身份尽量对应到应用名称，模块会在本机读取已安装应用列表；这些信息不会上传。

设置、应用驻留规则和运行记录保存在本机。驻留规则会保存所选应用的包名和 Android 用户 ID；系统能够识别来源时，运行记录也可能包含应用包名。运行记录通常保留约 14 天，最多 4096 条，存储上限约 12 MiB；存储压力较大时可能更早清理。可在“运行诊断”右上角菜单中选择“清除运行记录”手动清理。

默认复制会移除这些标识，但内容会进入系统剪贴板；完整报告可能包含应用和设备识别信息。只有用户主动复制或导出时才会生成可分享内容。开启“详细诊断日志”后，应用标识、UID 和 Hook 运行信息还会写入 Android/LSPosed 日志；排查结束后可关闭。“清除运行记录”会删除模块本机记录，但不会清除已经写入的系统日志。
